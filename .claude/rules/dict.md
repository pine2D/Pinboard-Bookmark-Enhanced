# 词典深水区：查词界面（在线词典 / 保存释义 / 查词卡）

> 2026-11-05 起词典规则拆成三份，按读到的文件分别加载：本文件管查词界面（在线词典、保存释义、查词卡布局与状态、负缓存）；`dict-entry.md` 管 AI 词条与补充的生成契约；`dict-pack.md` 管离线词典包（Yomitan / ECDICT / CC-CEDICT）与查词槽的本地支线。md-dict.js 三份都会加载。

## 在线词典不变量（md-dict.js）

- `dict2_` 缓存键保留大小写；查询链：原词精确 → 语义未命中后的小写候选 → 再未命中后的可选 lemma 参数（当前界面传空值，不为此生成 AI）。
- 只有 HTTP 404 与 HTTP 200 空/不可渲染结果属于**语义未命中**；超时、断网、429、5xx 和坏 JSON 都是**加载失败**，不能伪装成「没有词条」。实测（2026-07-29）：线上服务对查无此词返回 `200 + {"entries":[]}`，不是 404——404 分支是防御性保留（代理/上游变更），别当主路径读，也别因为「没见过 404」就删掉。
- Free Dictionary API 连续 3 次网络类失败后在本会话熔断 60 秒，父级 abort 不计失败；Wiktionary 兜底固定导航到 English Wiktionary，不是后台请求。
- `dict2_` 最多保留 **500 条缓存**（独立 LRU）；其他缓存仍最多 200 条（全局上限）。这不限制查词次数、`pbp-vocab` 生词数量或 CC-CEDICT 词条数；原词别名与实际命中词可分别占一条记录。

## 保存释义的默认选择

- 尚未存入生词本的词，默认保存释义（Q14=A）：AI 区块展开（屏上有已渲染的 AI 词条）时取 AI 的第一条，否则取词典结果按显示顺序的第一条可保存释义；只看 AI 区块是否展开，不依赖旧的视图状态。选择列表顶部解释默认规则，不要求用户每次手动选择。手动选择在本次查词中保留，异步结果或 AI 区块展开不得覆盖它；所选来源停用、删除或失效后清除该选择并提示重新选择。
- 已存生词的释义不随查词或词包升级自动改写。上条默认只用于尚未存过的词：已存生词（阅读器与资料库都如此，含资料库详情里的自动查词）不预选任何释义，在明确选义前闭合面停在「要保存的释义」、「更新」保持禁用（library 的保存按钮写「更新已保存的生词」；阅读器的保存条预览为提示文字、「更换」常显，页脚在「学习中 | 已掌握」旁显示禁用的「更新」，只有可选释义里没有任何一条会改动记录时才隐藏），选择列表顶部写 `dictMeaningSavedHelp`；是有意为之，不是 Q14=A 的漏选（2026-10-28 用户裁决，任务 3c、3d）。阅读器按当前 owner 读已存状态（`_pbpDictRefreshSave` 的读后结果记入本次查词的 `savedKeys`，`_pbpDictApplyVisibleChoice` 据此不套默认值），`pbpDictSaveCurrent` 在未选义时也拒绝写入，且没有显式选择时会在实时 owner 闸门之后自己再读一次生词本（命中或读取失败都拒写），以堵住展示读取未返回前就点击、按 Q14=A 默认值覆盖已存释义的窗口；渲染场景 `dict-save-saved`（阅读器）经生产生词库种入该词，SETUP 卡住无预选、更新禁用与已存说明。用户从选择列表选择解释并明确保存／更新后才写入；列表顶部分别说明默认、手选、已存或需重选的状态。完整词条与词源不是独立释义，不得因为排在前面就成为默认保存值。
- 阅读器保存条（3.2）：页脚首项是要保存释义的一行文字预览（`.xp-dict-save-preview`，只有一条可存时也显示，无可选释义时显示提示），另有其他可选项时跟「更换」按钮；预览与选项只写释义，所存词形与标题词不同时才加「词形 · 」前缀；点击才打开选择列表（`popover=auto`，不用 hover 浮层，左右边对齐查词卡的内容框，审计 `dictSaveMenuBox`），方向键 / Home / End 移动、Enter / 空格选择，Esc 与选择都把焦点还给「更换」，列表的 Esc 不再冒泡关闭弹层或侧栏。选择列表不提供「不选」项。library 沿用 `listbox.js` 的值盒子列表框（同为文字预览加点击列表，选项与闭合面同样只在所存词形与标题词——自由查词的词头或已存生词的词形——不同时加「词形 · 」前缀，审计 `dictSaveMenuChoices`；未选时闭合面的「要保存的释义」是隐藏选项，不在展开的列表里，键盘也到不了；已存生词在明确选义前，禁用的保存按钮已写「更新已保存的生词」），页脚在详情滚动区内吸底，贴住滚动区的可见下沿（抵掉详情区下内距，其下不露滚动内容），详情区按保存条实时高度留 `scroll-padding-bottom`，键盘聚焦的控件不落到条下；窄于 440px 时保存按钮仍带文字，只有重新查询是纯图标，文字过长时在按钮内按正文行高折行（单行仍是控件高，每多一行只加一个正文行高，图标对齐首行；dict-save-bar 场景按 en / de / fr 逐语种量）（2026-10-28 复查，任务 3b.2、3c、3d；审计 `dictSaveBarFlush` / `dictSaveBarFocus` / `dictSaveText`）。存入生词本用 `bookmarkPlus`，阅读器跳转资料库用 `library`，library 的「已在生词本」提示保留 `bookMarked`（Q26=A，状态而非动作）。保存仍先比对快照 owner、写入前再读实时 owner，两道闸门不变；朗读按钮固定读词头词形（查询词），不随下方来源或所选释义变化。

## 重设计裁决：查词界面部分（2026-10-26 起，批 0–3d 已落地）

用户已拍板，2026-10-26 至 10-28 分批施工完成（`e5ae24a6^..27915cee`，含首尾共 87 个提交），以下条目是现行契约、与上文一致；不得再扩充旧类别。依据、复盘与施工对照见 `docs/research/dictionary-content-value-2026-10-25.md`「复盘与重设计裁决」。

生成侧的裁决条目（补充收为三块、超额条目截取、没有补全动作、协议、失败账本、流式接入）在 `dict-entry.md`。

- **空结果本机负缓存**（1C.4 已落地，md-dict.js `pbpDictNegRecord` / `pbpDictNegForget` / `pbpDictNegHas`）：无来源或 AI 判定无此类内容时按 owner + 词形 + 语言对记在本机，不进 Drive、不进备份；文案写「本次检索未找到可核实原文」，不断言该词没有此类用法；再试须用户主动。每 owner 一个 local 聚合键 `pbpDictNeg:<ownerHash>`（`{entryKey: at}`，上限 500 淘汰最旧，读写在与账本同前缀的 Web Lock 里），`entryKey` = SHA-256(`[term, sourceLanguage, target 或 "", category]`)，检索类（examples、etymology 来源）不带目标语言，AI 类（patterns、confusables）带——取屏幕上已渲染词条的解释语言，补充请求也用这同一语言（界面或设置语言事后变了也不跟着漂），记录与读取因而对得上，不区分模型；某次渲染换了语言时按新语言清空并重读这份记忆（重读期间与首次渲染一样不显示学习块的付费按钮，读完或读取失败才出现，不会先显示普通按钮再改名；较早发出、属于旧语言的读取结果晚到时丢弃），更新词条、失败保存的纯保存重试与 Drive 同步刷新也按屏上词条的语言读写（只有首次生成用当前目标语言）；30 天过期（读时判、写时清）。只在受支持语言的干净未命中（原文用例 `[]`、词源检索 0 条，后者经 `pbpDictSupplementRun` 的 `onSources` 计数回调得知）与 patterns/confusables 的 `unsupported_usage` 时写入；不支持的语言、`source_failed`、`host_permission`、超时与取消一律不写。检索到结果、生成成功或 Drive 带来该类别的正记录（词源须带来源）即删除。读取先于按钮选择：原文用例块读完才显示动作行，学习块在首次渲染前读完；记住的状态在块小标题之下省略类别名，只显示「上次未找到 · 再试」（2026-10-28 裁决，让它在阅读器 480px 弹层里占一行；四个按钮——原文用例、搭配与句型、辨析、词源——一律如此，无障碍名仍含类别名，付费的再加模型名；用法要点块内两个按钮外观相同，各在自己的槽位标签之下，按钮下方再有一行按类别命名的中性说明；说明一律另起一行，不在按钮旁挤成窄栏）与中性 info 文案（检索类 `dictSupplementNoSources`，AI 类 `dictPatternsNone` / `dictConfusablesNone`），付费块仍是 `wandSparkles` + 模型名，再试即普通点击、重新付费。渲染场景 `dict-entry-paid-negative`（阅读器与资料库，带 AI 密钥）按 `DICT_PAID_NEGATIVE_LOCALES`（en / zh_CN / de / ru / pl / ja）逐语种用 controlRung 卡住按钮单行，`dictActionNoteBelow` 卡说明在按钮下方。写入前后重核当前 owner，ownerless 不写不读；已登记 `PBP_RECLAIM_CATEGORIES.misc`。
- **学习块槽位**（2026-10-28 裁决，已落地）：md-dict.js `learningForm` 给每个类别一个固定槽位 `.xp-dict-learning-slot[data-slot]`。用法要点块 = 块标题 → 「搭配与句型」槽位 → 「易混词辨析」槽位 → 学习偏好行，两个槽位各以一行类别标签 `.xp-dict-learning-label` 开头；词源块只有一个类别，块标题即唯一标签，槽位无标签行，结果也不再带同义的折叠标题。槽位只为当前学习设置服务（`existing()`：母语与水平都相同的最新未替换结果），按钮与结果二者只出现其一、至多一条无标题结果；为其他设置生成的结果（改了母语／水平，或 Drive 从设置不同的设备同步而来）放在槽位外、词源块之后（`data-ai-block="profile"`，折叠，标题「类别 · 母语：… · 学习水平：…」，搭配与句型只写母语，未设写「未指定」），仍可更新（沿用其设置），回执写在新版本自己的更新行。槽位里是本类别的当前结果（恒展开、`summary` 隐藏）及其更新按钮，然后是本类别的动作行（按钮或「上次未找到 · 再试」及其进度、保存回执、中性说明、alert）；生成、更新、失败、记住的未找到、只读旧记录（旧类别与此前版本仍在块外，带自己的标题）、缓存与同步渲染都不改槽位顺序，回执与 alert 只出现在所描述类别的槽位内——更新成功的回执写在槽位动作行，不随被替换版本收进「此前版本」。槽位按钮不重复类别名：可见文字为 `dictSlotGenerate`（各语种沿用「生成 AI 词条」的动词）或 `dictNegRetry`，加模型名；无障碍名为「类别 · 文字 · 模型」（`modelNotes` 按 `data-category-name` 刷新，更新补充按钮同样以类别开头）。结果取代按钮时焦点移到槽位标签（词源为块标题，均 `tabIndex=-1`），不滚动。学习偏好行与末个槽位相距 sp-4（与槽位间距相同）。渲染审计 `dictUsageSlots` 卡标签在本类别所有节点之上、搭配与句型先于辨析结束、偏好行不比槽位间距更贴近末个槽位；`dict-entry-legacy` 夹具另种一条其他设置的辨析结果。
