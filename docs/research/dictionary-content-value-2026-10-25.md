# 词源、相关词与 AI 补充用法：调研及实施备忘

日期：2026-10-25。用户已批准按本稿实施；本节保留实施前结论，完工后追加对照及复审记录。

## 目标与边界

面向不同母语、不同学习语言的使用者。解释、判断和引文释读默认使用明确设置的母语；手动指定 AI 释义语言时尊重该选择；未设置时明确显示回退语言。原词、例句和真实引文保留其语言，附译文。学习水平调节说明难度，不改变原文及事实。

维持现有查词入口与按需补充，不增加一排 AI 按钮。基础词条不发送文章或词典包内容；补充发送已生成词条、学习资料及必要公开证据。付费结果永久保留；更新由用户明确触发，创建新版本，完整结果与证据继续同步。

## 实施前问题

1. 文学/文化仅取前三条搜索摘要，没有读取原段落或检查体裁。Wikisource 也收录法律、报告等，正文命名空间不是文学分类。
2. 补充提示词要求不重复基础词条，但实际没有发送基础词条或其中的含义。
3. 母语只作背景资料；输出依赖释义语言，返回内容没有语言检查。
4. 七类补充统一返回单一 content 字符串，无法分别检查需要的内容与引用。
5. 词源与相关词缺乏结构：历史、现代构词、记忆联想未分层，相关词没有说明关系。

## 逐类内容规范

| 内容 | 用户价值与结果要求 |
| --- | --- |
| 词源 | 现代构词、可核实历史来源及其与现代意思的联系分开；没有历史资料就留空，不编拆字故事。 |
| 相关词 | 默认最多五个，说明词族、同源、近义或同主题关系及区别。 |
| 搭配 | 按含义组织表达形式、意思、场景、原创例句与译文；无语料统计不宣称最高频。 |
| 易混词 | 两三个真正容易混淆的词，同场景比较及选择原则，不编互斥规则；母语明确才讨论该语言对的假朋友词。 |
| 语体/地区 | 区分正式程度、领域、地区和语气；必要时给中性替代表达，没有显著差异不凑数。 |
| 语法 | 针对学习语言给最相关的一至三点：形式/句型、例句及解释；不统一套英语语法模板。 |
| 场景 | 二至三个不同交际目的的原创示例或短对话，结合可选主题与水平，明确为 AI 编写。 |
| 文化/网络 | 具体表达、圈层/平台、含义与语气、时间及可核实出处；一次命中不等于起源或流行程度。 |
| 文学 | 一至两例，含作者、作品、章节、真实短引、译意、情境及此处用词效果；排除法律、报告、目录与作品介绍。 |

保存释义菜单只负责保存，不暗中决定补充内容范围。补充接收基础词条，多义时明确分组。文本、结构、语言和证据分开验证；原文从取得的正文中提取，模型不得制造引文或 URL。无证据允许失败，不用空泛生成填充。

## provider 的核实例证

- [V2EX provider](https://www.v2ex.com/d/provider)：直接读取失败后经 Jina 读取。词源链条易理解，但相关词关系未标注；文学段只提《傲慢与偏见》《简·爱》以及 provide/provision 等相关表达，未给 provider 的具体引文，不能照用为实证。
- [Etymonline provider](https://www.etymonline.com/word/provider)：provider 是 provide 的行为者名词；provide 追溯至拉丁语 providere，涉及向前看、预作准备与供给。现代构词和历史来源应分开呈现，不把记忆提示当史实。
- [狄更斯《匹克威克外传》第十四章](https://en.wikisource.org/wiki/The_Works_of_Charles_Dickens/Volume_1/Chapter_14)：原文 “Thoughtful creature! Comfortable provider!” 出现在女主人介绍早餐后。provider 指提供生活照料的人；结合上下文可读出 Tom 对舒适生活的私心与喜剧意味，后者属于释读。
- [Edith Summers Kelley《Weeds》第一章](https://www.gutenberg.org/cache/epub/61201/pg61201-images.html)：原文 “as bountiful a provider” 用于家庭供养者评价，随后有按当地标准的限定。两个实例只能说明各段实际用法，不能证明文学中的频率。

## 方法与来源

- [SKELL](https://www.sketchengine.eu/skell/) 区分真实例句、搭配和相似词；自动相似词不一定同义。
- [Word Sketch Difference](https://www.sketchengine.eu/guide/word-sketch-difference-compare-words/) 用搭配差异帮助辨析，优于并排复制定义。
- [RAE CORPES XXI](https://www.rae.es/banco-de-datos/corpes-xxi) 强调文本种类、地区、时间及真实语料范围。
- [IDS grammis](https://grammis.ids-mannheim.de/progr@mm/6876) 与 [FundéuRAE depender de](https://www.fundeu.es/recomendacion/depender-con-la-preposicion-de/) 展示语言特定的句型和介词问题。
- [Wikisource 收录范围](https://en.wikisource.org/wiki/Wikisource:What_Wikisource_includes)、[MediaWiki 搜索 API](https://www.mediawiki.org/wiki/API:Search)：搜索片段不等于完整语境，必须另取正文与元数据。
- [Gutenberg 自动访问政策](https://www.gutenberg.org/policy/robot_access.html)：普通网站不能直接作实时抓取 API；未来精选语料应使用其允许的获取路线。本轮不接入实时 Gutenberg 抓取。

## 已批准的施工顺序与验收

1. 语言与释义上下文：默认规则可理解，明确用户选择优先；按已有释义组织补充。
2. 文学和文化取材：候选检索、正文、体裁/来源定位、精确词形匹配；无来源不调用 AI。
3. 分类输出：各类结构化内容，正确语言、必要字段、引文一致性和重复控制。
4. 展示：复用现有折叠与按钮，气泡精简、library 充分利用阅读空间；键盘、取消、错误及保存失败恢复完整。
5. 保存同步：新格式兼容旧结果，手动更新保留全部付费版本，原文证据随结果同步。
6. 复审：相关逻辑测试、跨语言/窄窗/主题渲染、快速折叠与减少动态效果、焦点/滚动、取消/迟到响应、跨设备格式与旧记录兼容；完成后对照本稿逐项记录实际结果和限制。

### 实际验证边界

- 上述首轮实施与复审没有调用付费模型；当时验证的是提示词、响应校验、展示、保存和失败恢复。后续经明确授权的真实调用见下节。实际模型对文学释读、语气及词源事实的判断仍需使用中评估；可靠语言检测不能证明每一句短文本都正确。
- 文学/词源结构识别目前覆盖 en、zh、es、de、fr、it、pt、ru、ja、ko。不同 Wikisource 的元数据并不齐全，宁可无结果也不猜作者、作品或章节；文化来源不保证覆盖所有新 meme。文学原文目前取一例合格结果，不承诺每个词都能找到。
- 真实 Wikimedia 首轮完整检索在已找到文学用例后遭遇 HTTP 429，未循环重试。已用真实公开 API 抓取响应离线重放，验证狄更斯 provider 的作品/作者/章节/原段，以及英语 provider、德语 Anbieter 的词源解析；修改为首例合格后停止后，没有继续请求线上服务。因此不宣称所有线上检索端到端通过。
- Drive 已用独立服务端形状夹具验证实际同步 runner、新旧批次和版本保留，未操作用户真实双设备。读新版结构的设备应更新扩展；升级后重新打开已有 reader/library 标签页，才能运行新版脚本。
- 不追溯修改旧付费内容。用户可以手动“更新词条”或“更新此补充”；更新会调用 AI、保留旧版，新旧内容及证据继续按当前账号同步。

## 真实 AI 验证与失败处理（2026-10-25 后续）

### 授权与验证范围

用户明确批准后，仅使用合成单词 `provider`，测试中文基础词条与“搭配与固定表达”。未发送用户文章、生词库或问答，未调用文学/词源取材及付费搜索。模型、地址以 `~/.config/ai-dev/providers.env` 为准；仅受限 Node 测试进程读取所需凭据，浏览器使用隔离账号和假 Key。Google Drive 未连接。

### 根据证据实施的修正

- 明确区分输出截断、空正文、模型不可用和 HTTP 402，并在词条或补充操作处给出具体恢复提示。更新失败保留旧版，未完成内容不存入词条。
- 词典两条生成路径要求完整输出。其他非流式消费者保留原有处理部分文本的行为；不会因为 HTTP 200 的截断/空正文自动追加付费重试。
- MiniMax 拒绝关闭思考后，尝试官方支持的 `reasoning_effort: low`，不通过模型名称名单判断。若该参数也被拒绝，可在既有四次总上限内剥离；明确参数拒绝与泛化错误分别处理，避免错误记忆污染后续调用。不普遍增加输出额度。

## 跨协议通用可靠性修正（用户纠正后）

### 已复现的公共缺口

- Gemini、Claude、Ollama 的非流式路径没有使用相同的完整输出检查；前两者只取首个文本块，可能漏掉思考块之后的正文。JSON 恰好闭合并不能证明模型已完成输出。
- 必需释义有效，但可选音标、词性、例句列表、学习辅助内容为 null/缺失时，整个词条被拒绝；明确的整数编号以字符串表达也被一律拒绝。此类差异与具体模型无关。
- 补充单字段上限与最终 12000 字符总上限不一致：各字段都合规，拼合后仍可能超限，而提示词此前未说明总量约束。
- 有效解释语言的本地名称未被小型别名表覆盖；短母语解释夹带较长原文术语时，字符占比可能误判成外语。语言标签仅比较基础语言，也会漏掉明确的书写体系冲突。

### 实施原则

1. **协议层统一结果。** 四类接口分别提取可见正文、完成/未完成/未知/拦截状态，再走一个公共检查；思考和工具载荷不当正文。兼容端点缺失终止元数据仍可交给严格词条解析，显式未完成则拒绝保存。拒答、空正文、响应 JSON/结构错误采用固定错误码，不记录模型正文。
2. **生成入口有限规范化。** 只转换语义明确的可空字段、单对象列表和规范整数字符串，然后执行原有严格校验；词头、语言、释义、义项范围、来源与引用不猜测。缓存、归档及同步仍使用既有严格格式，不重写旧付费内容。
3. **语言判断依据通用语言数据。** 使用标准语言标签、显式脚本和系统语言名称数据核对，避免为每个新模型补一张语言别名表。原文术语与解释正文分开考虑；证据不足不冒充高置信度语言判断。
4. **验证相同场景。** 用官方协议形状手写响应夹具，四协议运行同一类成功/失败情形，并检查实际生成、归档、重读和失败保留旧版。模型名使用任意自由文本；新增模型不应要求修改词典解析逻辑。

协议依据：[OpenAI Chat](https://developers.openai.com/api/reference/resources/chat)、[Gemini GenerateContent](https://ai.google.dev/api/generate-content)、[Claude stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)与[thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)、[Ollama chat](https://docs.ollama.com/api/chat)与[thinking](https://docs.ollama.com/capabilities/thinking)。供应商请求字段差异仍由现有薄适配层处理；这与词条业务逻辑针对具体模型打补丁不同。

所有模型运行相同的实际产品流程：存储配置解码 → Library / reader 的挂载按钮 → 公共 AI 适配器 → 词条／补充解析 → IndexedDB 归档 → 重读 → 展示。付费阶段使用同一份已核对、冻结的公开资料，修复检索后没有悄悄替换输入。Qwen 的词条案例耗尽两次后，缺失基础词条的补充测试复用已验证的 DeepSeek 合成词条，经过真实保存入口导入隔离档案并记录来源；这不代表 Qwen 词条生成成功。

### 找到的共性原因与实现

1. **输出被思考耗尽、页面过早超时。** 初测 DeepSeek Flash 两词均全思考截断，DeepSeek Pro 多类补充在 2048 处无正文；另有 HTTP 正常返回却被产品 30 秒期限拒绝。词典现统一请求 60 秒、8192 总输出上限与低思考偏好，仍限制条数与内容长度。其他任务默认值不变。较高上限可能增加最坏情况下的等待和费用，不要求模型用满，也不在内容失败后自动再生成。
2. **仅要求 JSON 不等于约束字段。** Qwen 有正常结束但引号未转义的响应；JSON object 模式下还出现半句解释被拆成额外字段。公共生成器现在给出闭合字段 schema，协议层负责格式映射及有界能力协商。仍严格解析，不丢弃未知字段后冒充完整解释，不猜补歧义 JSON。两份真实坏回答已审核后保存为离线反例。
3. **模型承担了无意义的元数据任务。** 五种原创补充没有外部来源，旧模板却要求模型返回来源编号，真实出现伪造的 0／1／2。现在这些类别不请求来源字段，由程序填入既有无来源标记；文化／文学仍必须引用已取得来源，越界、漏译或改写引文仍拒绝。
4. **类别指令互相干扰。** 文学曾混入普通搭配以凑满条数。现在 prompt 与 schema 按类别一致约束，文学条数受实际来源数限制，原文由程序插入；中文解释聚焦片段的用法、情境和表达效果，解读不能当作作品事实。
5. **格式合格仍可能内容残缺。** 真实存在可保存的半句话、把词语用法倾向说成硬性规则、将对比词全部翻译掉，以及语法补充重复构词知识。提示统一要求完整句、保留原词、减少无依据的频率与排他性判断，并让语法重点转到句法、搭配和可数性；最终引号指导用单引号表示正文引语，降低 JSON 分隔符歧义。没有新增“看起来像某种模型”的解析分支，也没有添加会误拒绝短释义的标点启发式。
6. **文化取材混入普通词命中。** 初测 based 的资料包含 unrelated 页面中的 based in/on。检索现要求独立词条或正文中明确作为表达提及的词，并可从同一词条取得多个完整段落，保留不同用法语境。匿名公开检索复核 10 次 GET 后取得 Based 的历史及现代使用段落；付费对照仍沿用原冻结资料，因此不能声称已实测新取材对全部生成结果的改善。

业务层没有供应商或模型名称分支。传输层的字段协商只依据协议与服务端拒绝，共用原来的四次尝试上限；每次重过权限、账号与取消检查。401、402、429、5xx、空正文、截断及内容校验失败不会触发此重试。

### 已实施的顺序与边界

本轮按用户批准的方案实施，真实测试总授权为不超过 100 次请求、US$10。实施与测试均不按模型名称分叉词典业务逻辑；供应商能力差异留在公共传输适配层。

1. **能力记忆按实际端点隔离。** 键包含 provider、规范化端点和 model，保存七天，最多 128 项。旧的仅按 provider/model 保存的记录不再影响新端点。只有服务端明确拒绝某个格式或思考参数时才做兼容协商；普通 400、认证、额度或内容失败不触发这种降级。未知兼容接口先使用 JSON object，避免先发不支持的 schema；原生协议仍使用其已有结构化能力。最小思考偏好只有在明确拒绝 `none` 时才改用 `low`，不把 `low` 宣称为关闭思考。
2. **基础释义独立完成。** 基础任务只生成词义、发音与短例句，不等待词源取材，也不申请 Wiktionary 权限。词源与相关词改为单独按需生成，并区分现代构词、历史、同族词、同源词、近义词和主题相关词；历史与同源判断必须绑定已检索的来源。原有词源内容和旧版归档继续保留。
3. **按独立项目验收补充。** 完整 JSON、词形、语言、来源与引文边界仍严格校验。某些独立项目无效时保留有效项目，并明确标记缺失数量；用户可主动补全，而不是自动付费重试。补全使用原补充对应的基础释义版本、原来源与已接受内容，不让后来更新的词条改变原义项编号，也不替换已接受项目。
4. **取材失败局部隔离。** 一个搜索或候选页失败不会丢掉其他已核验来源；权限撤销、账号切换及取消仍立即中止。有实际来源读取错误且没有可用来源时，报告取材失败，不冒称“资料中不存在用例”。文学父页元数据继续寻找，直到作者与体裁均取得，仍受原候选／请求／时间上限限制。
5. **缩小单次教学任务。** 各类别只选少量有价值的区别，摘要一句、说明一至三句。文学强调引文中这个词的具体作用，禁止由短摘录推断人物身份、家族关系、情节或时代频率；词源只能转述对应片段，不能凭记忆补中间语言、词根或语义演变。相关词标题保留实际外语词形，可点击继续查词。
6. **反馈跟随操作位置。** 检索、生成、核对与保存状态显示在当前补充按钮附近；保留取消、失败后旧内容、只重试保存和键盘焦点恢复。部分结果可见且可单独补全。Drive 新写入使用归档传输 schema 3，继续读取 schema 1／2／3，并原样重试旧版冻结批次；没有改 IndexedDB 数据库版本。

| 语法 | 给出可数性、限定词、of／for／to 及复合名词结构 | 有偏向“怎么翻成中文”或将常见结构说成唯一结构的回答；语言正确不能证明教学目标正确 |
| 场景 | 工作沟通的选型、故障、采购与家庭责任有不同例句 | 个别例句译文添加未明确的人物指代，或者把场景补充写成中文商务写作建议；语义一致性尚无自动保证 |
| 文化与网络用法 | 能用中文解释 based 的语义转变，保留可追溯来源 | 固定资料覆盖面有限；政治圈层／当下频率仍可能被过度概括，不能用历史记载证明现在的普遍程度 |
| 文学 | 七模型均返回中文解释、原文和译文；收紧后减少长篇情节推断 | **仍有明显译错**：古旧拼写被译成季节或职业，双重否定被反转，推测被译成肯定；部分解释仍推断人物身份。不能把这些结果称为内容质量合格 |

文学复测的具体反例包括 DeepSeek Flash 将 `footer` 译作“秋天”、Qwen Max 译作“冬天”，Gemini 3.8 的否定关系变化，以及 Gemini Lite 添加原文没有的“三月冰”。这些是本次合成词公开引文的观察，不构成模型排行，也不转化为某个模型或词语的硬编码补丁。

本轮没有以放宽引文校验、吞掉不完整 JSON 或静默移除错误内容来取得上述完成率，也没有为每条结果增加隐藏的付费审校请求。进一步的内容优化应优先解决三件事：基础义项一条一义；明确学习对象是源语言、母语仅负责解释；文学优先提供含目标词的短完整引文与母语释读，长段翻译另行明确选择，并保留否定、指代和不确定性。**这些后续质量方向尚未实施或证明有效**，需用新词、新材料及独立语义标准验证，不能将再次改写提示词等同于问题已修复。

## 复盘与重设计裁决（2026-10-26）

本节记录 10-24 至 10-26 查词改动的复盘结论，以及用户当天拍板的重设计方向。下列内容是**已裁决、待施工**的目标，不代表代码已经实现；施工完成后在本节末尾追加对照与验证记录。复盘材料（五路调研、六份方案及对抗评审、202 张夹具截图）保存在会话临时目录，结论已归并到本节。

### 复盘结论

- **规模膨胀，任务面没有缩小。** 两天 61 个提交：`md-dict.js` 被改 27 次（1849→2882 行），`md-preview.css` 查词规则块 68→167，新增文案 key 247 个（其中查词 62%），补充类别 0→8，查词面板内 9 个折叠块、10 个按钮。补充生成与校验连续 9 个提交在加固外围，界面对齐修了 5 轮；类别只增不减。
- **“全绿”指标自洽而不覆盖用户路径。** 第二轮 98/98 只覆盖 4 个英文常用词、中文解释、冻结证据、LiteLLM 兼容入口、未连 Drive。非英语词、实时检索、权限申请、Drive 生成前同步门均未测；补充失败只写 `console.warn`（`md-dict.js` usage generation failed），真实使用中的失败分布没有数据。渲染审计是场景完成检查，阅读器表面没有几何断言，因此对齐问题会复发。
- **“成功率”分三层，需分开报告**：生成链路（受测条件下 100%）、用户真实路径（未知）、内容是否合格（确定有问题：文学误译、语域判断绝对化、易混词与语域重复）。文化类要求同名条目，普通词基本没有来源，且从不展示所依据原文；文学要求整段翻译最长 600 字的古旧文本，是误译的主要来源。
- **界面问题的结构原因**：一个面板里三套来源规则互相冲突（词典纵向堆叠、AI 整屏替换、保存菜单拍平全部来源但默认值只看当前视图）；免费导航与付费动作共用控件（同一位置轮换 4 种无文字图标，同一按钮在查看已保存与生成之间换义）；状态反馈散在 4 处且全为灰字；字号 8 个 em 档加 3 个 px 档，三层间距同为 16px，折叠标题比内容右移 8px。

### 内容方向：八类收为三块

| 现类别 | 去向 | 依据 |
| --- | --- | --- |
| 搭配、语法 | **用法要点**之“搭配与句型” | 都讲如何用该词造句；非英语的格支配、助词、性数一致等句型要点保留在本节 |
| 易混词、语域 | **用法要点**之“辨析” | 两轮人工复审均为“重复、判断过强”；语域以与近义词对比的方式写 |
| 场景 | 删除，话题输入一并删除 | 用法要点每条自带例句；话题参与复用匹配，导致同一按钮在免费与付费间切换 |
| 文学 | **原文用例** | 只摘含目标词的一句原文及出处，AI 只释读这一句并允许回答“无法可靠释读”；原文与译文覆盖同一段文本 |
| 词源 | **词源**（保留） | 以 Wiktionary 原文为依据，AI 用解释语言忠实转述并给构词与相关词；源语言站点原文对初中级学习者不可读 |
| 文化／网络 | 删除，旧记录只读 | 普通词几乎没有来源，价值低 |

- 用法要点一次请求生成一张卡；原文用例一次点击，先检索、找到原文才调用 AI；词源同理。付费调用从最多 8 次降到 1 至 3 次。
- 已付费的旧补充全部保持可读并标注为旧类别；归档类别白名单只增不减，界面可生成列表与归档可读列表分开维护。
- 基础义项“一条一义”（如 charge 多义被并为一条）是补充引用义项的前提，列为同期内容问题。

### 协议与校验裁决

- 保持 JSON 与现有 schema 协商（原生协议沿用 schema 约束，兼容端点用 json_object），按节组织单个对象；不改用 JSON Lines，不合并基础词条与补充为一次请求，截断结果仍不得保存。
- **超额条目截取**（用户裁决）：某节返回条数超过上限时保留前 N 条、丢弃多余，不算失败，也不计入可补全的 `omittedItems`；超额不等同于坏成员，坏成员仍按原规则逐条处理并记录。
- **删除“补全”付费动作**（用户裁决），只保留用户主动触发的重新生成；部分结果照常保存并注明。
- 语言检查改为逐条做脚本检查，再对剔除源语言字段后的合并文本做一次统计检测；提及剥离与提示词的引号约定保持一致（修正提示词要求 ASCII 单引号而剥离规则不剥离的冲突）。
- 没有来源时，词源条目类型枚举不提供“历史”“同源”；话题不再参与复用匹配（话题输入本身随场景类别删除）。
- **空结果本机记住、不同步**（用户裁决）：检索不到来源或 AI 判定“该词没有此类内容”时，按 owner、词形、语言对记在本机，显示“上次未找到”并提供用户主动再试；不进 Drive、不进备份。界面口径写“本次检索未找到可核实原文”，不断言该词不存在此类用法。
- 本机失败账本只记错误码、阶段、类别与时间，不记词形和内容，按 owner 隔离，作为后续优化依据。

### 界面裁决

- **单列堆叠**（用户裁决），不叠加“词典 | AI 词条”分段：气泡头部已有解释／翻译／词典分段，侧栏外层已有提问／查词页签，多词典产品也普遍分组堆叠。顺序为：词头与发音 → 词典结果（每个来源一个小标题）→ AI 词条（未生成时一行生成按钮）→ 学习补充（用法要点、原文用例、词源固定顺序；未生成为一行按钮，已生成即内容）→ 全卡一次的模型／日期／解释语言 → 吸底保存条（文字预览要保存的释义，配“更换”，只有一条可存时也显示）。
- **付费按钮保留 `wandSparkles`**（用户裁决），一律图标加文字，旁注**仅模型名**（用户裁决，不显示 token 估算或金额）；同一控件不在免费与付费之间换义，导航永不花费，失败不自动重试。
- **“AI 优先、缺失时生成”保留**（用户裁决），生成期间词典结果照常显示，AI 词条在其区块内就绪，不自动跳转视图。
- 状态分语气：错误用危险色与 warning 图标；部分结果与“未找到”用中性语气与 info 图标；反馈靠近触发位置，生成开始时焦点留在面板内的进度位置。
- 规范：字号四档加一个元数据档；间距三级；只有两条左缘，单义项也保持缩进；原句用正文色、译文用次要色（修正当前倒置）。存入生词本统一 `bookmarkPlus`，跳转资料库用 `library`。
- 先为 render-audit 开阅读器查词表面并加左缘一致、不溢出视口的几何断言，再改结构。
